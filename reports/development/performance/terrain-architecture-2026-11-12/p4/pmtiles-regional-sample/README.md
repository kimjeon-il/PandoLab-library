# PMTiles v3 포장 보조 실험

앱 실험 코드 `6f09503cd`, 중국 2×2 LOD5 표본. 1024 타일 4개 또는 같은 영역의 512 타일 16개를 [공식 PMTiles Python 3.8.1 구현](https://github.com/protomaps/PMTiles)으로 별도 v3 아카이브에 넣고, 공식 Reader로 모든 타일을 복원해 기존 WebP의 크기·SHA-256과 일치시켰다. Wheel SHA-256은 `report.json`에 기록했고 운영 환경에 설치하지 않았다.

| 타일 | 원본 합계 bytes | 아카이브 bytes | 차이 bytes |
|---|---:|---:|---:|
| 1024, 4개 | 5,324,720 | 5,325,069 | 349 |
| 512, 16개 | 5,293,268 | 5,293,655 | 387 |

현재 LOD5의 지구 전체 2:1 격자에 맞춰 1024는 PMTiles 주소 zoom 6의 64×64 공간에 43×22 격자를, 512는 zoom 7의 128×128 공간에 85×43 격자를 사용했다. 나머지 주소는 빈 슬롯이며 빈 타일 파일을 저장하지는 않는다. 이는 EPSG:4326의 판도 전용 인덱싱으로, 일반 Web Mercator XYZ 클라이언트는 메타데이터만으로 이를 올바른 지리 위치에 놓지 못한다. 전용 주소 매핑과 날짜변경선·극지 처리가 필요하다.

이 값은 작은 표본의 파일 포장 크기와 로컬 복원 검증만 나타낸다. 전체 세계 피라미드, 브라우저 range 요청·캐시·전송량·지연, 운영 호스트 호환성과 실제 뷰어 성능은 평가하지 않았다. COG처럼 하나의 큰 아카이브는 제공 호스트의 파일 크기와 범위 응답 제약을 따로 검증해야 한다.
