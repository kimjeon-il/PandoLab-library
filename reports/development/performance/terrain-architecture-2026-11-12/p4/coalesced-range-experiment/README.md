# 검증 구간 병합과 동시 요청 공유

앱 실험 커밋 `82278c79a`, 64KiB SHA-256 검증 구간을 최대 8개까지 한 HTTP 범위로 묶었다. 기존 64KiB 단일 구간 결과와 같은 지역·타일·호스팅을 사용했다. PMTiles는 Fastly jsDelivr, COG는 기존 CDN 경로이다. 각 결과는 신규 브라우저 컨텍스트에서 3회 반복한 원본 JSON에 기록했다. 인접 구간을 병합하되 각 구간 해시를 검증하고 모든 검증 성공 후 캐시에 넣는다. 여러 요청이 겹친 경우 전송을 공유하며 한 소비자의 취소가 다른 소비자를 취소하지 않는다.

| 자료 / 타일 | 기존 64KiB 요청 수 | 수정 후 요청 수 | 기존 및 수정 후 응답 본문 |
|---|---:|---:|---:|
| PMTiles / 1 | 19 | 4 | 1,245,184 bytes |
| PMTiles / 4 | 82 | 12 | 5,325,069 bytes |
| COG / 1 | 62 | 10 | 4,063,232 bytes |
| COG / 4 | 110 | 19 | 7,153,745 bytes |

초기 병합 구현은 동시 요청을 공유하지 못해 COG 4개에서 34~35회, 12,941,555~13,007,091 bytes를 전송했다. `coalesced` 원본은 그 실패를 보존하고, `coalesced-fixed` 원본은 중복 공유 수정 후 결과다. 수정 후에도 개별 WebP 4개는 4회 5,324,720 bytes이므로 이 결과만으로 COG가 우세하다고 판정할 수 없다.

정상·손상·범위 오류, 동시 읽기, 개별 취소, 전체 취소 후 재시도, 캐시 0과 캐시 축출을 다룬 해당 단위 검사 9개가 통과했다. 이는 별도 브라우저 전송 실험이며 정식 Viewer의 실제 사용자 네트워크나 GPU 성능이 아니다. CDN과 공유 네트워크 캐시는 통제하지 않았고, 제한된 한 지역과 타일 묶음이다. 병합은 실험 옵션이며 기본 런타임 정책을 바꾸지 않았다.
