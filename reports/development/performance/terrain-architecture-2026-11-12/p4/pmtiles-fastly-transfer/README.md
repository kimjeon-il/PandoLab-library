# Fastly의 WebP·PMTiles 범위 전송 실험

앱 실험 코드 `9fb047315`, Chromium 151.0.7922.34. 같은 `fastly.jsdelivr.net` 호스트에서 중국 2×2 지역의 고정 커밋 1024 WebP와 이를 그대로 담은 고정 커밋 PMTiles를 비교했다. [공식 PMTiles JS 4.5.0](https://github.com/protomaps/PMTiles)으로 주소를 읽고 브라우저에서 구간 길이·Content-Range·구간 SHA-256 및 복원된 타일 SHA-256을 검사했다. 각 실험은 WebP–PMTiles–PMTiles–WebP–WebP–PMTiles 순서의 새 컨텍스트 세 반복과 같은 페이지 Blob 재사용을 포함한다. 네 원본 JSON에 실행별 수치와 해시가 있다.

| 읽는 타일 | 방식 | 구간 크기 | 첫 요청 수 | 응답 본문 bytes | 첫 요청 ms, 세 반복 |
|---|---|---:|---:|---:|---|
| 4개 | 개별 WebP | 해당 없음 | 4 | 5,324,720 | 3,600.7 / 561.6 / 562.9 |
| 4개 | PMTiles | 64KiB | 82 | 5,325,069 | 602.6 / 598.0 / 580.9 |
| 4개 | PMTiles | 512KiB | 11 | 5,325,069 | 585.4 / 576.4 / 574.4 |
| 1개 | 개별 WebP | 해당 없음 | 1 | 1,164,846 | 146.0 / 138.0 / 139.2 |
| 1개 | PMTiles | 64KiB | 19 | 1,245,184 | 158.6 / 152.9 / 152.5 |
| 1개 | PMTiles | 512KiB | 4 | 2,097,152 | 234.7 / 229.5 / 233.9 |

1개 직접 WebP의 다른 구간 실험 반복은 163.5 / 137.7 / 138.5ms였다. 같은 페이지 재사용은 두 방식 모두 네 타일 약 89ms, 한 타일 약 20ms였고 네트워크 요청은 0이었다. 구간 해시가 64KiB인 구현은 요청을 늘리고, 512KiB는 한 타일만 읽을 때 응답 본문을 늘렸다. 4개 시험은 아카이브의 모든 타일이 필요해 파일 전체를 받았다. 이런 요청 수와 초과 전송량은 선택한 검증 구간·배치 구현의 결과이지 PMTiles 형식의 고유 한계가 아니다.

첫 WebP 실행의 지연 편차가 크고, CDN edge·DNS·공유 네트워크 캐시는 통제하지 않았다. 한 지역·한 파일·한 기기의 소규모 단독 전송과 디코딩 실험이지 Viewer/GPU 성능, 세계 자료 또는 실제 사용자 통계가 아니다. 별도 기본 `cdn.jsdelivr.net` 경로는 같은 PMTiles 파일의 범위를 잘못 반환한 바 있으며 Fastly 결과가 모든 CDN 경로의 무결성을 보증하지 않는다. 판도 전용 EPSG:4326 인덱싱은 일반 Web Mercator XYZ와 다르다.
