# W2-P5-2 Windows GTX 1650 공유국경 Worker 경합 검증

**판정: 제한적 완료. B1 실사용 개선 실패, B2 실제 전환 개선 미확정.** 진단 후보는 제품 최적화가 아니며 적용을 권고하지 않는다. 전환 중 Worker 오류 롤백, 초기 패킷의 정확성상 필수 여부, 자연 경합에서의 B1 인과 효과는 미확정이다.

## 환경 및 방법

- 2026-11-02 Windows, NVIDIA GeForce GTX 1650 드라이버 32.0.16.1088, Chromium 151.0.7922.34, WebGL2 ANGLE Direct3D11, GPU compositing enabled. 각 실측 브라우저의 CDP SystemInfo와 unmasked renderer를 원시 JSON에 저장했다.
- 제품 소스 `fe8282ba32761ab9586348d1712e11cc1f4e7882`, 라이브러리 핀 `5eb7be55208efaafe39bd5a65ec2f111d70b9053`, runtime `data-f50b7f480c812df6f5ea0c40f5461ab0`; viewport 1280×800, canvas 1280×752, DPR 1, ko-KR, Asia/Seoul, 2026-11 ↔ 2025-12. GPU scheduler step 256KiB.
- 기존 detached `w2-p3-after`를 읽기 전용으로 사용하고 제품 JS, WASM, GIS를 변경하지 않았다. 계측 및 후보는 메모리 snapshot만 사용한다. 새 브라우저 프로세스를 최초 전환마다 생성했다. OS 파일 캐시는 비우지 않았다. 각 조건의 예열 표본 20회는 하나의 마지막 브라우저에서 수집했다. CDP trace 사용자 마커의 같은 타임라인을 사용했으며 Worker `performance.now()`를 메인 시계에서 직접 빼지 않았다.
- 측정 중 외부 `worktree-storage.mjs` GIS 캐시 작업 PID 14456을 관찰했다. `environment-observations.txt`에 시각을 기록했다. 해당 작업의 CPU/디스크 간섭 가능성이 있으며 표본은 제외하지 않았다. A2 10회 중 4회는 Worker 요청이 없는 다른 경로를 탔다. 무작위화하지 않은 순차 표본이므로 작은 차이나 개선율을 인과적 효과로 단정할 수 없다.

B1 p50은 A 대비 28.1% 느리며 A2와도 유사하게 느리다. 후보 비교 2건은 모두 엄격한 전체 입력 직렬화 SHA 불일치로 native 경로로 돌아갔고 **실제 결합/최신 세대 인증은 0건**이다. 이 불일치가 어떤 필드에서 생겼는지는 확인하지 못했다. 따라서 동일 핵심 형상/소유/품질을 보여 주는 Worker 키가 있더라도 본 진단의 전체 입력이 같다고 주장하지 않는다. 새 요청이 있는 B1 8건의 약 13,308,618바이트 입력 복제는 434.9–472.7ms, 직렬화·UTF-8은 140.7–144.8ms였다. 이 동기 비용과 더 큰 Long Task가 유력한 악화 기여 요인이지만, 개별 기여도를 독립 조작해 증명하지는 않았다. B1의 SHA 계산과 복제는 초기 요청에도 적용되므로 탐색 시작부터 최초 전환 표시까지 중앙값 A/B1/A2는 약 20.26/21.29/20.70초였으며, 이를 일반 앱 체감 로딩 수치로 해석해서는 안 된다(자동화 준비 대기 포함).

A의 새 Worker 요청 6건에서 post 종료부터 해당 Worker 첫 리스너 진입까지 p50 0.052ms, 최대 0.121ms이고 이전 패킷의 동기 계산과 이 대기 구간의 겹침은 0/6이다. A2의 같은 Worker 대기 p50 0.048ms(6건). 자연 256KiB 표본에서 W2-P4-2 1MiB 조건의 큰 Worker 경합은 재현되지 않았다. 리스너 이전 큐·복원 비용은 별도로 분해할 수 없다. B1의 대기는 native 요청만 대상으로 하고 결합 없음과 별도로 읽어야 한다.

## 초기 화면과 요청 타임라인

`baseline-analysis.json`은 첫 연도 요청을 0으로 정렬한 10개 trace와 각 형상 SHA를 담는다. 예: A-1 최초 화면 승인 −661.941ms, gen1 req3 패킷 계산 시작 −2678.938ms, 끝 +812.130ms, 결과 전송 +816.585ms. 첫 화면 승인 자체가 해당 full packet 계산 완료보다 앞선 것은 사실이다. 별도 3회 초기 상태에서 canonical mesh/physical ready와 `pendingBoundary:true`를 관측했고 초기 PNG는 지도·국가·지명을 보여준다. 하지만 화면 승인에 선행된 다른 경계 자원의 완전성이나 초기 gen1 결과가 이후 표시 정확성에 필요한지는 이 관측만으로 증명할 수 없다. 따라서 초기 패킷의 필수 여부는 **미확정**이며 B1은 기존 계산 결과를 보존한다.

같은 254개 국가의 geometry SHA, 국가 ID·소유 root·parent·quality·outline을 연결한 기존 Worker identity는 기준 표본에서 일치했지만 실제 B1의 더 엄격한 전체 입력 SHA는 두 후보에서 일치하지 않았다. 두 키의 차이는 단순 동등성 증거로 대체하지 않았다. 첫 화면·전환 스크린샷은 `p5-initial-*-initial.png`, `p5-*-cold-*-0.png`에 저장했다. 대표 이미지를 직접 확인했으나 전체 픽셀 동등성은 주장하지 않는다.

## B2 변경 입력: 별도 합성 Worker 통제

실제 표시 중인 2026 지도를 수정하지 않고 캡처된 254개 국가 snapshot 중 하나의 `boundaryRootId`를 변경해 격리 Worker에서 실행했다. 형상 SHA는 유지되고 전체 입력 SHA는 달랐다. 동일한 테스트 전용 checkpoint barrier와 메시지 순서를 A/B/A2에 적용했다. B만 이미 완료된 sequence 검사 뒤, 동기 패킷 계산 **진입 전** obsolete 작업을 취소한다. 이미 실행 중인 동기 JS/WASM을 선점하지 않는다. 각 조건은 신규 Chromium 10회다. 결과는 새 독립 Worker가 계산한 패킷의 메타데이터와 모든 TypedArray SHA 기준 출력에 30/30 일치했고 실제 지도 상태 SHA는 실험 전후 일치했다.

| 체크포인트 이후 (ms) | A | B | A2 |
| --- | ---: | ---: | ---: |
| p50 / p90 / 최대 | 7526.1 / 7942.6 / 8218.1 | 4101.4 / 4330.8 / 4398.7 | 7571.8 / 7709.5 / 7865.2 |
| obsolete 취소 | 0/10 | 10/10 | 0/10 |
| 해시 검증 비용을 별도 합산한 p50 | 8001.8 | 4569.6 | 8057.9 |

B의 체크포인트 이후 중앙값은 A보다 45.5% 짧고 A2에서 복귀한다. 이는 **별도 합성 프로젝트의 통제된 Worker 비용**으로, 실제 연도 전환이나 지도 표시의 개선율이 아니다. 해시 비용 합산 값은 측정된 별도 순차 검증을 더한 참고값이며 전체 지도 임계경로라고 표현하지 않는다. 이 조건에는 85ms 유예나 350ms 인위적 계산을 넣지 않았다. 변경 입력의 실제 지도 A/B/A2 및 예열 20회는 수행되지 않았고 실제 지도 개선은 미확정이다.

## 정확성, 오류와 메모리

- 완료된 실제 전환의 문서 국가·형상·관계·timeline·지명 텍스트/좌표 해시는 날짜별로 A/B1/A2 전부 일치했다: 2025-12 `84eeed0ee1b2268b7e841a121416355205dc20c306feb89373e58b18ff086ad5`, 2026-11 `e6010b615633fac3f1eef040f2a7a6a018937d86535c96b76d19d335ead31789`. 캔버스 스크린샷은 정상 지도를 확인했으나 모든 픽셀과 모든 지리 속성을 독립 검증한 것은 아니다.
- A/B1 메모리 실행의 stale 요청 ID·프로젝트 세대·형상 revision·quality 응답 4건 모두 거부, 전후 해시 일치. 진단 단위 검사에서 동일 입력 인증, 상이 형상/소유/quality/outline native fallback, 새로운 세대, 중간 patch 순서, Worker 오류, 비동기 전송 오류 처리 통과. 기존 취소 합성 단위 검사 3건은 고정 소스의 LF 정규화 snapshot에서 통과했다. 원래 work/ui 직접 실행은 Windows CRLF와 LF 고정 anchor 불일치로 3건 실패했고 원인과 로그를 보존했다. 단위 실험의 85ms/350ms는 실GPU 성능 값이 아니다.
- 기존 브라우저 회귀의 WebGL context loss/restore, Worker 오류 후 reload, 정상 연도 왕복은 통과. 별도 전환 중 Worker 오류 주입은 두 번 모두 주입 응답 관찰 시간 초과다. 첫 시도는 진단 마커에 없는 메시지를 검색한 검사 오류이고 수정 후 재시도도 시간 초과였다. **전환 중 rollback과 빠른 연속 취소는 검증되지 않았다.**
- 20회 연속 표본의 GC 후 A 공유국경 Worker heap은 136,089,396→136,089,608 bytes, B1은 132,458,408→132,458,620 bytes. 공유국경 Worker WASM은 각 72,548,352 bytes 유지, 캐시 추정 16,556,996 bytes / 96MiB, 보관 배열 detached false. 메인 heap과 Chromium private/working set의 전후 값, GC 이전값과 각 Worker의 계측은 원시 JSON에 있다. 각 브라우저 종료 후 해당 CDP 프로세스 ID 잔류 없음. **20회 범위에서는 급격한 잔존 증가가 관측되지 않았으나 장기 누수 부재는 미확정**이다. 메모리 샘플은 GC 및 메모리 검사로 교란되므로 성능 분포에 포함하지 않았다.
- 별도 입력 반응성 실험과 전환 중 빠른 취소 재현은 실행하지 못했다. Long Task만으로 실제 입력 지연을 대체하지 않는다.

## 원본과 재현

`comparison.json`, `baseline-analysis.json`, `protocol-analysis.json` 및 각 `p5-*.json`, `protocol-changed-*.json`, `*-trace.json.gz`, PNG, console log, `instrumented-*` snapshot, `synthetic-worker-emitted.js`, `analysis-source/`를 보존했다. `snapshot-reproducibility.json`은 기준 12개 계측 소스 재생성을 확인한다. 최초 실패 로그 및 시험용 pilot도 보존하며 통계에서는 제외했다. 각각의 trace는 독립 CDP 단조 시계이므로 서로 다른 trace의 절대 시각을 직접 비교하지 않는다.

앱 저장소 `work/ui`의 `tools/w2-p5-2-*.mjs`와 기존 `w2-p3-after` 및 고정 데이터 캐시가 필요하다. `PANDOLAB_W3_EVIDENCE`를 **새 빈 증거 폴더**로 지정한 후 `node tools/w2-p5-2-server.mjs`, 별도 터미널에서 `node tools/w2-p5-2-run.mjs baseline`, `node tools/w2-p5-2-join-server.mjs`와 `node tools/w2-p5-2-run.mjs join`, `node tools/w2-p5-2-run.mjs baseline-retest`를 순서대로 실행한다. 측정과 trace 분석을 병렬로 실행하지 않는다. 합성 변경 입력은 서버 4221에서 `W5_PROTOCOL_SCENARIOS=changed node tools/w2-p5-2-protocol.mjs`에 해당하는 환경 변수 설정을 사용하며, 강제 checkpoint의 결과를 자연 경합으로 취급하지 않는다. 기존 파일이 있으면 runner는 덮어쓰지 않고 중단한다. 보관된 snapshot과 실제 계측 소스·근거를 먼저 확인할 것.

## 후속 조사

1. 실제 새 요청과 선행 계산이 겹치는 자연 조건을 안전하게 재현하고 초기 공유국경의 첫 화면 정확성 기여를 픽셀 및 게시 상태로 입증한다.
2. B1에서 전체 입력 SHA가 다른 필드를 추적하고, 정확성상 유효한 canonical identity를 증명하기 전에는 세대 재인증 또는 캐시 재사용을 제품에 적용하지 않는다. 동기 13MB 복제/직렬화의 UI 비용을 줄이는 별도 설계가 필요하다.
3. 실제 변경 입력의 지도 전환에서 B2 취소가 마지막 표시 조건을 개선하는지, 안전한 초기 화면 보존과 빠른 취소·오류 롤백이 성립하는지 다시 측정한다.
