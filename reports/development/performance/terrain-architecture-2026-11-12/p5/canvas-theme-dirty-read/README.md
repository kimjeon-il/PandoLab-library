# Canvas 타일 테마 재사용과 부분 읽기

앱 `bb89767a9`는 이미 준비된 DEM 타일의 현재 테마 외 한 테마를 기존 96MiB 타일 예산에 여유가 있을 때만 보관한다. 전환 시 같은 비트맵을 재사용하고, 예산 압박 시 타일 자체보다 보조 테마를 먼저 닫는다. 예산에 여유가 없으면 기존처럼 재계산하고 이전 비트맵을 닫는다. 해당 동작의 합성 단위 검사는 재사용·압박·한도 없음과 자원 정리를 확인했다. 실제 Viewer 프레임 또는 사용자 GPU의 성능 검증은 하지 않았다.

Node에서 1026×1026 합성 타일의 어두운 테마 색상 변환은 237.4 / 256.8 / 257.6ms, 밝은 테마는 256.8 / 253.4 / 254.2ms였다. 각 테마의 육지·바다 RGBA 두 평면은 합계 8,421,408바이트다. 이는 개별 변환 비용의 예비 측정이지 저장 효과나 Viewer 지연 개선의 실제 측정이 아니다.

별도 Chromium headless/SwiftShader 실험에서 이미 준비된 1280×800 Float16 화면을 먼저 통째로 읽고, 같은 화면의 사각형 영역을 읽었다. 세 반복의 전체 8,192,000바이트는 2.8 / 2.8 / 2.7ms, 중앙 1/4인 2,048,000바이트는 0.8 / 0.8 / 0.9ms, 우측 1/8인 1,024,000바이트는 0.6 / 0.6 / 0.6ms, 모서리 1/16인 512,000바이트는 0.4 / 0.3 / 0.3ms였다. 읽은 모든 채널은 전체 읽기의 대응 값과 일치했다.

전체 읽기가 항상 먼저라 캐시 및 순서 효과가 있으며 변경·투영·색상 계산·실제 Viewer와 GPU 동기화 비용은 측정하지 않았다. 부분 읽기는 수치 Canvas 운영 경로에 아직 연결하지 않았으며, 카메라·타일·마스크 변경 시 올바른 변경 영역과 이전 프레임 무효화 조건을 증명해야 한다. 원본 JSON은 dirty-read.json과 theme-conversion.json이다. Canvas 수치 화면 보간 및 대표 지역 실제 화면 검증은 미완료다.

앱 `fa680d406`의 추가 실험에서는 독립된 두 화면에 같은 오른쪽 160×800 영역을 그린 후 각각 전체 화면과 바뀐 부분만 읽었다. 세 반복의 전체 읽기는 7.7 / 8.3 / 4.2ms, 부분 읽기는 2.1 / 1.9 / 2.1ms였다. 부분 입력 1,024,000바이트는 전체 8,192,000바이트의 대응 영역과 모든 Float16 채널이 같았다. 실제 Viewer가 아닌 합성 화면이며 마스크, 회전·확대 시 전체 무효화와 부분 색상 재합성의 비용은 포함하지 않는다. 원본은 dirty-update.json이다.
