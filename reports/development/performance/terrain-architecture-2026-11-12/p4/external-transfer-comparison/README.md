# 같은 CDN의 WebP와 COG 소규모 전송 실험

앱 실험 코드 `93e63238d`, Chromium 151.0.7922.34, 로컬 실험 페이지와 jsDelivr 외부 HTTPS. GitHub 고정 자료 커밋 `0fc425921e1fb431ef35d9af6f5ac762f2b3a269`의 중국 동일 영역 1024 타일 4개를 사용했다. WebP의 바이트 해시와 COG의 범위 해시·복원 화소 해시를 확인하고, 각각 이미지를 디코딩했다. 후보 순서는 WebP–COG–COG–WebP–WebP–COG이며 매 반복 새 브라우저 컨텍스트에서 첫 요청과 같은 페이지 캐시 재사용을 측정했다. 전체 원본은 `report.json`이다.

| 후보·상태 | 소요 ms, 세 반복 | 요청 수 | Resource Timing 전송 bytes |
|---|---|---:|---:|
| WebP 첫 요청 | 10,260.4 / 693.5 / 631.7 | 4 | 5,325,920 |
| COG 첫 요청 | 1,208.7 / 1,255.7 / 2,450.5 | 110 | 7,186,745 |
| WebP 메모리 재사용 | 89.7 / 106.2 / 95.3 | 0 | 0 |
| COG 메모리 재사용 | 82.0 / 82.2 / 83.7 | 0 | 0 |

WebP는 검증된 원본 Blob, COG는 검증된 부분 읽기에서 생성된 PNG Blob을 메모리에 재사용하고 두 경우 모두 이미지 디코딩을 다시 수행했다. COG 응답 본문 합계는 7,153,745바이트, WebP는 5,324,720바이트이며 Resource Timing 전송값에는 HTTP 오버헤드가 포함된다. 첫 WebP 반복은 나머지와 큰 편차를 보여 세 반복만으로 지연 우열을 확정할 수 없다.

브라우저 컨텍스트는 새로 만들었지만 CDN edge·DNS·공유 네트워크 캐시는 통제하지 않았다. Viewer/GPU 표시 시간, 전체 지구 자료, 512 타일 및 실제 사용자의 네트워크를 측정한 결과가 아니다. COG 메모리의 PNG 재인코딩과 WebP 캐시 방식도 Viewer의 GPU 텍스처 캐시와 다르다. 큰 30MB COG는 같은 CDN의 20MB 제한으로 거부됐다.
