# Core 런타임 최적화 측정 및 검증 결과

> 보고서 ID: PERF-20261104-CORE · 상태: 측정 결과 확정, 전체 과제 미완료 · 기준일: 2026-11-04
> 코드: 최종 6fec9113349e606e64dc4deaf13b4bae84939355 / 비교 WASM 원본 a0a080496 · 데이터 핀은 각 P0 첨부에 기록

## 대상과 방법

Windows의 실제 Chromium 뷰어, 1280×800, 2026-10-31 고정 시계. 동일한 현재 JS와 데이터로 각각 최적화 전 WASM 및 최종 WASM을 사용했다. 기준 WASM은 Git 객체에서 추출하여 해당 manifest의 SHA-256과 대조했다. 두 P0 첨부의 codeRevision은 실행 당시 코드이며, 기준 WASM의 실제 출처는 위 별도 커밋이다. 20회 반복 연도 전환의 p50/p95와 Worker 동기 호출 시간을 측정했다. 라우팅은 HTTP 캐시를 끄므로 같은 페이지 반복은 HTTP 캐시 적중률이 아니다.

출처 준비가 여전히 큰 비중을 차지한다. 별도의 심볼 빌드로 세 번 전환한 Worker CPU 표본 1,874개에서는 JSON 파싱, SHA-256, 할당·해제가 상위에 나타났다. 진단 WASM은 배포용과 바이너리가 달라 함수 번호를 배포용으로 대응시키거나 직접 시간 비교하지 않는다. 외부 핸들·검증·무효화 계약 때문에 세대 간 자료 캐시를 임의로 유지하지 않았다.

최종 빌드에서 새 브라우저 컨텍스트 3회 준비 관측은 18.03 / 18.21 / 18.25초, 같은 컨텍스트 새로고침은 17.44 / 16.92 / 16.58초였다. OS 디스크 캐시를 지우지 않았다. 프로세스 작업 집합 합계와 JS 힙 원자료는 startup-memory.json에 있으며 공유 페이지 중복, WASM/GPU 메모리 및 다른 프로세스 경계 때문에 전후 메모리 개선을 주장하지 않는다. 준비 시각은 최초 표시 프레임 시각이 아니다.

## 검증 및 열린 문제

- 네이티브 Core 관련 5개 CTest, WASM 관련 11개 집중 테스트, 변경 실행기 관련 4개 단위 테스트 통과. Windows WebView2 검수 앱 실제 실행에서 최종 Core 산출물 및 읽기 전용 계약을 확인했다.
- 전체 단위: 4,246개 중 4,070 통과, 2 실패, 174 건너뜀. Windows–Ubuntu Caspian 결과의 엄격 바이트 비교 실패, 로컬 지도 분석 Gazetteer 보고서 판본 연결 실패는 미해결이다. Windows–Ubuntu 비교에서 관찰한 좌표 최대 차이는 약 6.4e-14도이고 원본 데이터나 허용 오차는 변경하지 않았다.
- 전체 브라우저: 111개 중 104 통과, 5 실패, 2 건너뜀. 실패 다섯 건 단독 재실행에서 지도 품질 1건은 통과, 물리 지형·Canvas 프레임 완료·프로젝트 열기·작은 화면 검색 4건은 다시 실패했다. 원인 미확정이며 성공으로 간주하지 않는다.
- 전체 린트는 자동 승인 검토가 범위 제한을 이유로 거절했고, 관련 변경 파일 린트는 통과했다.
- 사용자 승인 후 main을 fast-forward했으며 Pages 실행 https://github.com/kimjeon-il/Pando/actions/runs/41818001264 은 공개 코드·데이터와 뷰어 시작·연도 전환 검증을 통과했다. 공개 WASM SHA-256은 61b8e6addc8e6cf3195fa4deea0417ed784564c507ecd38140e644e1dd8326a1이다.
- 검사 인자 전달 실수로 기존 test-results가 제거됐다. 삭제된 전체 목록은 복원하지 못했다. 이 보고서의 전후 P0 원본은 Git에서 기준 바이너리를 되살려 별도 경로에서 재측정했다. 실행기는 패키지 관리자 --를 안전하게 처리하도록 수정하고 회귀 검사를 추가했다.
