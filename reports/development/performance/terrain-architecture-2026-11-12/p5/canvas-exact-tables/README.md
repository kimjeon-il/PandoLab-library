# Canvas 타일 색상 준비: 정확한 수치표

앱 `474b1ec4a`, 비교 기준 `656e1bae6`. 정수 고도·8비트 음영의 PCHIP 육지색, 해양 깊이, 음영 배율과 정치 지형 기울기를 Worker에서 최초 사용 시 Float64 테이블로 준비해 기존 1024px 타일의 매 픽셀 삼각함수와 PCHIP 반복을 줄였다. 색상을 미리 정수로 반올림하지 않고 기존과 같은 계산 순서로 최종 RGBA8을 만든다. 라이트·다크 모두 사용하면 테이블의 고정 배열 용량은 총 428,160바이트이며 기존 DEM 타일의 캐시 예산과는 별도다.

동일 Node 프로세스에서 1026×1026 합성 타일을 라이트·다크 각 세 차례 순서대로 변환했다. 기존 라이트 261.4 / 276.2 / 291.9ms, 개선 라이트 108.8 / 93.9 / 97.3ms; 기존 다크 313.2 / 274.4 / 297.0ms, 개선 다크 99.5 / 102.5 / 119.3ms였다. 매회 육지·바다·정치 세 출력의 전체 픽셀 SHA-256이 각각 이전 결과와 동일했다. 첫 개선 변환에는 해당 테마 테이블 생성이 포함된다. 원본 수치와 입력·소스 해시는 `probe.json`이다.

측정은 Node의 CPU 타일 변환으로, 동일한 하드웨어에서 이전 구현을 먼저 실행하는 순서이며 브라우저·실제 Viewer 프레임·네트워크·GPU가 아니다. 현행 캔버스의 고도 샘플별 색상 캐시를 더 빨리 만들 뿐, 화면에서 고도를 먼저 보간한 뒤 색상을 계산하는 기능은 구현하지 않는다. 정확성·캐시·공유 LOD·합성 WebGL 집중 검사 26개는 통과했으나 실제 Viewer 화면·대표 지역 프레임 검증은 미완료다.

별도의 먼저 실행된 개선 구현 단독 측정은 라이트·다크 각 3회의 원본 `standalone.json`에 보관한다. 같은 합성 타일이나 동일 프로세스 전후 비교가 아니므로 위의 짝지은 표본을 우선한다.
