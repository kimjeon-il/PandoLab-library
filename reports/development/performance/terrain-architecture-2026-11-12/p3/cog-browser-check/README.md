# 브라우저 COG 범위 읽기 기초 실험

`cog-fixtures/southwest-china-block256.tif`의 SHA-256 `4dd2131d6c79c96ccf9c9b49a82648ccbc51c4083ded26941d94d6b46eef43fa`, 크기 2,540,157바이트에 대해 64KiB 구간별 해시를 만들었다. Chromium 151과 geotiff.js 3.0.5의 브라우저 번들을 사용해 동일 출처 로컬 HTTP 서버에서 범위별로 가져오고 각 청크의 206 응답, 정확한 Content-Range, 길이와 SHA-256을 확인한 뒤에만 디코딩했다. 결과 원본과 모든 청크 해시는 `report.json`에 있다.

1024·512·256 세 단계에서 각 100×100 창을 읽은 결과, 독립 원본 입력에서 해당 창을 추출한 RGB 해시와 모두 일치했다. 세 단계 창 읽기에 7개 범위 요청, 총 458,752바이트를 받았고 캐시 적중은 5회였다. HTTP 200 전체 응답, 잘못된 Content-Range, 바뀐 청크 바이트는 각각 거부했다.

이 결과는 로컬 동일 출처의 하나의 고정 COG에 대한 디코더·무결성 기능 시험이다. 현재 GitHub raw 호스트의 CORS 문제를 해결하거나 전체 파일의 SHA만으로 부분 바이트 무결성을 보장하는 것은 아니다. 브라우저 메모리 상한·실패 복구·Viewer 파이프라인 및 타일 방식 대비 성능은 아직 측정하지 않았다.
