# Canvas Float16 수치 보간과 비용 실험

앱 `00f5433a5`. Chromium 151 headless/SwiftShader, 같은 PC의 1280×800 합성 단일 육지 타일 장면이다. 시간 측정 입력은 고도 0m와 음영 212가 균일한 단순 자료이며 복잡한 실지형의 부하를 대변하지 않는다. 실제 Viewer·구형 브라우저·지구본·물리적 마스크·국가색·다중 타일이나 GPU 메모리 측정은 포함하지 않는다. 두 후보 모두 기존 운영 Canvas에 연결하지 않았다.

고도 한 채널과 음영을 담은 Float16 Canvas를 확대해 하드웨어 이미지 보간을 사용하고, 결과를 Float16 ImageData로 읽어 PCHIP 색상 테이블을 적용했다. 고도 8m와 520m를 4화소로 확대했을 때 네 고도 오차는 0m였다. 2×2 고도·음영의 4×4 합성 육지 색상은 정확한 CPU 참조 대비 RGB 최대 2 이하를 확인했다. 이 두 합성 표본은 전체 고도 범위·바다·해안·극지·모든 브라우저의 정확도 증거가 아니다.

Float16 두 번째 실행의 3회는 draw 1.8 / 0 / 0ms, getImageData 33.7 / 22.8 / 21.2ms, 근사 색상 계산 29.1 / 31.1 / 28.0ms, putImageData 4.7 / 4.6 / 4.2ms였다. 같은 보고 범위 내 직전 CPU 조회 래스터의 비교용 scanline 실행은 86.7 / 83.7 / 75.3ms, 동일 페이지의 기존 색상 이미지 그리기와 한 화소 읽기는 109.6 / 11.2 / 9.1ms였다. 첫 실행 및 JIT·캐시, 데이터 분포와 API 차이로 실제 서비스 성능이나 같은 장면 전체의 종합 비용을 뜻하지 않는다. Float16 지원과 색상 읽기·재사용 비용을 별도의 실제 기기에서 더 측정해야 한다.

정확한 선택된 수치 색상·기존 WebGL 비교와 합성 검사는 14개가 통과했다. 이 시제품은 8비트 색상 조회표 근사를 포함하고 실제 Canvas의 동일성이나 성능 개선을 증명하지 못해 채택하지 않았다. 원본 JSON은 initial.json, gradient.json, scanline.json이다.
