# W2-P6-5 — Windows GTX 1650 국가 형상 델타 성능 검증

**판정: 제한적 완료.** P6-3 델타는 실제 1992→1991 전환 10/10에서 사용됐고 표시 중앙값을 같은 조건의 A/A2보다 약 4.3–4.5% 줄였다. 이 구간은 여전히 약 5.1초이며, 2026→2025 최초 전환 10회에는 Worker 새 요청이 없어 효과를 입증하지 못했다. 실측한 변경 연도 한 방향에서는 개선이 재현됐지만 모든 연도와 장기 운영으로 일반화할 수 없으므로 제품 전체 성능 채택은 추가 검토가 필요하다. 제품 브랜치로 P6-3을 통합하지 않았다.

## 기준과 환경

- Windows, NVIDIA GTX 1650 드라이버 `32.0.16.1088`, Chromium `151.0.7922.34`, WebGL2 ANGLE Direct3D11, GPU compositing enabled. 각 샘플의 CDP `SystemInfo.getInfo`와 unmasked renderer를 JSON에 저장했다.
- A/A2 `ee6efddb7335a6665647cc69951e40103830c3e8`, B `0af8b63d2efbeb19e9b677ec23d5f3fb92abfb83`, 데이터 핀 `5eb7be55208efaafe39bd5a65ec2f111d70b9053`, runtime `data-f50b7f480c812df6f5ea0c40f5461ab0`. 두 소스의 차이는 P6-3 전송 helper/renderer/Worker 및 관련 테스트·CI·문서다. 실제 GIS·WASM은 변경하지 않았다.
- viewport 1280×800, canvas 1280×752, DPR 1, ko-KR, Asia/Seoul, GPU scheduler 기본 256KiB. 고정 Git 객체에서 메모리로 빌드한 독립 진단 서버를 사용했다. Viewer transition mark와 Worker 관측은 같은 방식으로 양쪽에 적용했고, 제품 파일과 표시 승인 조건은 변경하지 않았다.
- 2026-11→2025-12는 A/B/A2 각각 신규 Chromium 프로세스 10회, 예열 20회다. OS 파일 캐시는 초기화하지 않았다. 1991-12↔1992-12는 실제 국가 수명 변화가 있는 구간이며 A/B/A2 3회 순서 후 추가 A/B/A2 7회 순서로 각 10회 수집했다. 느린 표본을 제외하지 않았다.

2026→2025의 B p50은 A보다 1.36% 느리고 A2와도 유사하다. B 10/10, A 9/10, A2 10/10에서는 최초 전환 동안 새 공유국경 Worker `postMessage`가 없었다. A의 나머지 1건은 254개 full 요청이었고 2842.5ms였다. 따라서 B에서 이 구간의 델타 적중률은 0%가 아니라 **새 Worker 요청이 없어 산정 불가**다.

1991→1992는 A/B/A2 모두 246개 형상을 10/10 전체 전송했다. 반대 1992→1991에서는 A/A2가 242개를 10/10 전체 전송했고 B가 10/10 델타로 242개 중 1개 형상만 전송하고 241개를 생략하며 4개 삭제 ID를 전달했다. B의 지도 표시 p50은 A보다 244.2ms(4.55%), A2보다 227.9ms(4.26%) 짧았다. 10개씩 순차 표본의 독립 비모수 bootstrap으로 B 중앙값−평균(A/A2 중앙값)의 추정치는 −236.1ms, 기술적 95% 구간 −300.5~−209.9ms다. 이는 비무작위 한 PC·한 날짜쌍의 기술 통계이며 다른 경로에 대한 보장은 아니다. 전체 10회 모두 2.5초를 넘었다.

## 전송과 지연 분해

별도 진단 A/B/A2 한 쌍씩의 1992→1991 공통 CDP 시각이다. 각 구간은 연속 경계이며 중첩 시간을 합하지 않는다. Worker 리스너 이전은 엔진 복원과 큐 대기를 별도로 식별할 수 없다.

| 단계 (ms) | A | B | A2 |
| --- | ---: | ---: | ---: |
| 메인 `postMessage` 호출 | 186.9 | 1.6 | 190.2 |
| post 종료→Worker 리스너 | 229.4 | 2.6 | 231.7 |
| Worker 형상 digest 구간 | 106.4 | 9.6 | 109.9 |
| digest 완료→패킷 계산 시작 | 636.2 | 636.9 | 635.0 |
| 패킷 준비 계산 | 2988.2 | 3020.9 | 2973.4 |
| 패킷 계산 종료→메인 수신 | 111.5 | 136.8 | 110.3 |
| 메인 수신→국경 게시 | 349.8 | 335.5 | 332.9 |
| post 시작→국경 게시 | 4608.6 | 4144.4 | 4583.6 |

델타는 전송·리스너 이전 대기·digest를 줄였지만 캐시가 미적중인 패킷 재계산 약 3초가 남는다. GPU stroke의 CPU 업로드와 실제 GPU 실행시간을 각각 분리 측정하지 못했으며 게시 대기를 GPU 실행 시간이라고 주장하지 않는다. 비교 성능 표본의 최대 Long Task A/B/A2는 393/377/375ms다.

별도 강제 동일 형상 재준비에서 A/B/A2 각 3회, B는 토큰 확인 후 254개 중 254개 형상을 생략했다. JSON UTF-8으로 추정한 메시지 크기는 full 13,308,801 bytes, B delta 394,998 bytes(약 97.0% 감소)다. 추정 과정에서 별도 JSON 직렬화가 실행돼 시간에 영향을 주므로 이 표본을 자연 전환 시간과 합치지 않는다. 이는 Chromium structured-clone 내부 실제 바이트 수가 아니라 동일한 외부 표현 크기다.

## 정확성·복구·메모리

- 모든 완료 전환의 날짜별 국가·국명·형상·관계·지명·좌표·timeline 상태 해시가 A/B/A2에서 일치했다. 대표 스크린샷에서 지도·국경·지명이 표시되는 것을 확인했다. 이는 원시 데이터 전체에 대한 독립 GIS 재검증은 아니다.
- P6-3의 실제 Node Worker와 전송 helper 집중 검사 5개 통과: 검증된 형상 재사용, 1e-8도 변경, 소유·메타데이터 변경, 삭제/신규, 잘못된 토큰·삭제 집합 거부 및 fresh full 패킷/TypedArray 동등성. 고정 B Worker를 테스트용 경로에 로드했으며 product 소스는 쓰지 않았다.
- B Viewer에서 강제 재준비의 254개 생략 및 패킷 캐시, Worker 오류를 전환 중 주입했을 때 날짜·상태 보존과 canvas 픽셀 차이 0, 재시도 성공을 확인했다. 빠른 요청으로 선행 읽기를 무효화하는 회귀도 D3D11에서 통과했다. 현재 요청 ID·세대·형상 revision·quality와 다른 응답 4종은 거부됐고 상태 해시가 유지됐다. 첫 stale 진단 시 주입 anchor 들여쓰기 불일치 실패는 `stale-console.log`에 보존했고 수정 후 성공했다.
- WebGL context loss/restore 최초 검사에서 복원 직후 해시가 달라 실패했다(`w65-B-webgl.json`). 별도 재시험은 안정화 대기 후 날짜와 상태 해시가 복원돼 통과했다. 따라서 즉시 복원 완료라고 주장하지 않는다.
- 각 조건 60회 연속 자연 전환에서 0/10/20/40/60회 GC 전후 힙 및 프로세스 메모리를 수집했다. B 공유국경 Worker GC 후 heap은 136,058,696→136,059,156 bytes, WASM 72,548,352 bytes, 패킷 보유 추정 16,556,996 bytes(상한 96MiB) 유지. 보관 TypedArray는 detached false였다. A/B/A2 종료 후 조사한 브라우저 프로세스 잔류는 없었다.
- B의 별도 강제 재준비 60회는 **60/60 delta**, 모든 완료 상태 해시 일치. GC 후 Worker heap 136,058,300→136,113,192 bytes, 보유 패킷 16,556,996 bytes. 60회 관측 범위에서 계속 증가하는 누수는 보이지 않았으나 더 긴 운영 수명까지 보장하지 않는다.
- 각 조건의 별도 포인터 입력 3회 전환 표본에서 이벤트 시간→리스너 p90 A/B/A2는 16.29/15.8/16.28ms, 최댓값은 143.5/159/142.7ms였다. 자동 포인터 입력의 표본 수와 타이밍 한계가 있으므로 실제 사용자의 전체 입력 지연 보장이나 통계적 차이라고 단정하지 않는다.

## 원본·후속 작업

`summary.json`, `history-summary.json`, `bootstrap-summary.json`, `diagnostic-analysis.json`, 각 원시 JSON과 `*-trace.json.gz`, 스크린샷, `browser-regression.log`, 실패 및 재시도 로그, `analysis-source/` 및 SHA-256 목록을 보존한다. 사용자 정의 포인터·강제 재준비·진단 trace는 주 성능 표본과 분리했다. p95/p99는 표본이 부족해 사용하지 않았다. 서로 다른 Worker의 performance.now를 직접 빼지 않고 진단 trace의 공통 CDP 시계를 사용했다.

잔여 병목은 변경 시 전체 패킷 재계산 약 3초, state 준비 약 0.64초, 메인 수신 이후 게시 약 0.33초다. 1991→1992에서 B가 full로 돌아간 이유와 초기 base 인증 시점은 추가 분석 대상이다. 자연 경로에서 여러 역사 연도·형상 편집·토큰 불일치 후 resync를 반복 검증하고, 즉시 WebGL 복원 화면의 일시 차이를 원인별로 조사한 후 채택을 결정한다. P6-3 소스는 기존 격리 브랜치에만 있으며 main 병합·배포를 하지 않았다.

## 재현 절차

Pando `work/ui`에 수록된 `tools/w2-p6-5-*.mjs`, 두 고정 커밋의 Git 객체, 실행 당시와 동일한 데이터 materialized cache 및 Node/Playwright Chromium을 사용한다. 기존 증거를 덮어쓰지 않도록 `PANDOLAB_W3_EVIDENCE`는 새 빈 결과 폴더를 사용한다. 첫 화면 시점은 2026-11이어야 한다. 코드와 데이터 정체성은 두 서버와 브라우저 JSON에서 재확인한다.

```powershell
$env:PANDOLAB_W3_EVIDENCE = 'D:/dev/PandoLab-library-data/reports/.edits/ui/development/performance/<new-scope>'
$env:W65_SOURCE = 'ee6efddb7335a6665647cc69951e40103830c3e8'
$env:W65_PORT = '4261'
node tools/w2-p6-5-server.mjs
# 다른 터미널: 같은 증거 경로, B 소스와 포트 4262로 서버 실행
$env:W65_SOURCE = '0af8b63d2efbeb19e9b677ec23d5f3fb92abfb83'
$env:W65_PORT = '4262'
node tools/w2-p6-5-server.mjs
# 측정 터미널: 위 증거 경로를 지정하고 A, B, A2를 순서대로 실행
$env:W65_ARM = 'A'; $env:W65_PORT = '4261'; $env:W65_SOURCE = 'ee6efddb7335a6665647cc69951e40103830c3e8'
node tools/w2-p6-5-run.mjs
$env:W65_ARM = 'B'; $env:W65_PORT = '4262'; $env:W65_SOURCE = '0af8b63d2efbeb19e9b677ec23d5f3fb92abfb83'
node tools/w2-p6-5-run.mjs
$env:W65_ARM = 'A2'; $env:W65_PORT = '4261'; $env:W65_SOURCE = 'ee6efddb7335a6665647cc69951e40103830c3e8'
node tools/w2-p6-5-run.mjs
```

변경 연도는 동일 환경에서 `tools/w2-p6-5-historical.mjs`를 A/B/A2 순서로 실행한다. 기본은 조건당 3회이며 추가 7회는 `W65_START=3`, `W65_COUNT=10`으로 두 번째 A/B/A2 순서를 수행했다. 각각 별도 `force`, `input`, `memory`, `diagnostic` 스크립트와 B의 `force-memory`, `stale`, `webgl` 스크립트를 단독 실행해 원본을 만들었다. 작업 중 사용한 실제 진단 코드·브라우저 테스트는 `analysis-source/`에 보존했다. 분석은 측정이 모두 끝난 다음에 실행한다.
