# 512 타일 WebGL 묶음 그리기 1차 확인

기존 B512 Actions `43182296112`, 앱 `e01adf3752ba22e46fe34dfc92aed4f7ba0376c8`; 실험 묶음 B Actions `43194856533`, 앱 `73b5d6521f28058074fa259e147f062ee6e57d0a`. 중국 서남부 32배, 동일 Q1 원본과 512 타일·색상, 각기 다른 Linux Chromium SwiftShader 실행기, 1280×752 지형 단독 frame이다. 한 번씩이라 성능 순위나 GPU 성능을 판단할 수 없다.

묶음 후보는 최대 3×3 타일을 독립 gutter와 함께 atlas에 담고 같은 격자의 타일을 WebGL2 인스턴스로 제출한다. 해당 32배 수용 프레임에서 묶음 호출을 확인했다. 준비 중 기존 타일 경로가 38회 사용됐고, atlas 2개를 생성했으며 추가 크기는 19,022,112바이트다. 반복 그리기에서는 atlas를 재사용했다. 지원되지 않는 LOD나 예산에서는 기존 경로를 사용하며, 묶음 그리기가 확인되지 않은 장면을 B의 성공으로 간주하지 않는다.

지형 RGB 단일 프레임 비교에서 채널 최대 차이 1, 2 초과 화소 0이었다. 서로 다른 실행의 비교로 같은 시점의 모든 비동기 계층까지 증명하지 않는다. 마지막 장면의 전체 직접 GPU 제출 횟수는 개별 B512 170회, 묶음 B 140회로 기록됐지만 독립 실행의 단일 관측이며, 프레임 시간 개선은 입증하지 않았다. atlas 추가 메모리와 로딩·이동·컨텍스트 복구·실 GPU 비용 및 세 반복 비교가 남았다.
